## 3. 逐项升级说明

### 3.1 Go 1.27（双端建议升级）

- **收益**：
  - `encoding/json` 底层切换到 json/v2，反序列化显著提速（FVCC/FVCS 协议解码密集型场景直接受益）
  - 新增 goroutine leak profiler（`/debug/pprof/goroutineleak`），排查调度器协程泄漏非常有用
  - post-quantum 加密（crypto/mldsa）支持
- **风险**：低。Go 1 兼容性承诺内，无破坏性大改。
- **注意**：FVCS 侧 `go-sqlite3` 是 CGO 依赖，升级 Go 后必须重编验证（见步骤 5/6 捆绑策略）。

### 3.2 Gin v1.12.0

- **结论**：已是最新版本，**无动作**。
- **参考**：Gin v1.12.0 要求 go >= 1.25（go.mod 声明 go 1.25.0），与 FVCC 当前版本匹配。

### 3.3 gorilla/websocket（FVCS 需升级）

- **当前**：FVCS v1.5.1（2023-10-18）
- **目标**：v1.5.3（2024-06-14）
- **理由**：
  - v1.5.2 及更早存在弱 PRNG mask key 漏洞（GO-2026-6278），升级到 v1.5.3 修复
  - 与 FVCC 侧版本（v1.5.3）对齐，减少双端行为差异
- **风险**：低。补丁级升级，API 无变化。

### 3.4 Fyne v2.8.0（FVCS 升级，高风险）

- **当前**：v2.7.1
- **目标**：v2.8.0（2026-07-13）
- **更新内容**：
  - GPU 加速绘图原语（Ellipse、BezierCurve、ArbitraryPolygon、Blur、Shader）
  - RichText 增强（Markdown 支持）
  - 多显示器桌面 window API
- **⚠️ Breaking Change**：
  - `Polygon` 类型改名为 `RegularPolygon`（ArbitraryPolygon 加入后更名）
  - 1000+ commits / 800+ 文件变更，UI 回归量不小
- **风险**：高。必须单独做，托盘 UI 全面回归测试。

### 3.5 go-sqlite3（FVCS 升级）

- **当前**：v1.14.19
- **目标**：v1.14.48（2026-07-13）
- **说明**：CGO 驱动，SQLite 内核同步到 3.53.x；落后 29 个版本含多轮 bugfix 与安全修复。
- **风险**：中。需重编 + 任务持久化回归（任务表、断点恢复直接依赖）。

### 3.6 TypeScript 5.7 → 7.0（ui-src 升级）

- **路径**：5.7 → 6.0（过渡）→ 7.0（原生 Go 版，比 6.0 快约 10 倍）
- **注意**：
  - TS 7 走 `--erasableSyntaxOnly` 方向，enum / namespace 等非可擦除语法受约束，**升级前先清理代码中的 enum / namespace 使用**
  - 与 Vite 同一前端构建链，合并回归

### 3.7 Vite 6 → 8.0（ui-src 升级）

- **路径**：6 → 7 → 8
- **说明**：Vite 8 是 Vite 2 以来最重大架构变化——bundler 统一为 Rolldown（Rust 单引擎），构建快 10-30 倍，插件生态兼容。
- **注意**：
  - 当前构建链 `tsc -b && vite build` 需验证 tsc（或 TS 7）+ Rolldown 的组合
  - Tailwind 3.4 + PostCSS 插件在 Vite 8 下兼容性先验证（若准备上 Tailwind 4 一并对齐）

## 4. 升级顺序（8 步执行计划）

整体策略：**先 FVCC 后 FVCS、先低风险后高风险、Go 升级与 CGO 依赖重编捆绑**。

| 步骤 | 项目 | 动作 | 风险 | 验证点 | 回滚方案 |
|---|---|---|---|---|---|
| 1 | FVCC Go | 1.25 → 1.27 | 低 | `go build` + `go test ./...` 全绿；协议编解码回归 | 改回 go.mod 版本号，重编 |
| 2 | FVCS gorilla/websocket | v1.5.1 → v1.5.3 | 低 | `go build` + WS 连接/心跳/任务推送回归 | git revert go.mod + go.sum |
| 3 | Vite | 6 → 7 → 8 | 中 | `npm run build` 成功；前端页面全部路由可访问 | 回退 package-lock.json |
| 4 | TypeScript | 5.7 → 6 → 7 | 中 | 先清 enum/namespace；`tsc -b` 无类型错误；与步骤 3 合并回归 | 回退 package-lock.json |
| 5 | FVCS go-sqlite3 | v1.14.19 → v1.14.48 | 中 | CGO 重编；任务建表/读写/断点恢复回归 | git revert go.mod + go.sum |
| 6 | FVCS Go | 1.22 → 1.27 | 中高 | 与步骤 5 一起重编 CGO；全量 `go test ./...`；任务恢复、日志、鉴权回归 | git revert + 旧版二进制备份 |
| 7 | Fyne | v2.7.1 → v2.8.0 | 高 | **单独做**；修 Polygon→RegularPolygon；托盘 UI 全功能回归 | git revert + 旧版二进制备份 |
| 8 | 双端联调 | 全量回归 | 中 | FVCC↔FVCS 协议互操作：任务下发/进度/断点续传/代理生成 | 双端回退到上一版本 |

### 执行注意事项

1. **步骤 3、4 合并执行**：同一前端构建链（`tsc -b && vite build` 一起验证），但 TS 分 5→6→7 两跳、Vite 分 6→7→8 两跳，**不要跳版本**。
2. **步骤 5、6 合并执行**：CGO 重编一次搞定，Go 升级与 go-sqlite3 升级捆绑回归。
3. **步骤 7 必须独立**：Fyne v2.8.0 有 breaking change，涉及托盘 UI 全部回归，不与 Go 升级混做。
4. **每步先备份**：升级前 `git stash` 或打 tag（如 `pre-upgrade-20260917`），go.mod/go.sum 变动保留可回退点。
5. **升级顺序原则上不交换**：低风险先行验证流水线，高风险最后兜底；若中途失败，立即回滚该步，不带着半成品进入下一步。

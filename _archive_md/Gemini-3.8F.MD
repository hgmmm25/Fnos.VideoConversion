# FVCC 主页视觉与交互评估报告 — Gemini-3.8F 摘要

> 原始评审稿（约 14KB）已于 2026-10-14 压缩为本摘要；完整内容曾整合进 `docs/FVCC_任务页视觉改进整合方案_v1.6.1.md`（随 v1.6.4 批次 A/B/C 交付）。评审主体：`ui-src/src/pages/tasks.ts`；约束：零框架、冷灰调性不变、低性能 NAS（fnOS）设备访问。

## 核心结论

主页视觉提升的核心不是堆砌特效（大面积模糊/持续动画），而是**「信息层级解压缩」与「状态语义强化」**。仅通过 DOM 局部微调、Tailwind 类重组、局部更新去重即可显著提升工业级质感。

## 体检（5 短板，表格化）

1. 元信息排版冲突与层级扁平——`sub` 容器同时声明 `truncate` 与 `flex-wrap`（CSS 规范中二者冲突），多标签时省略号与折行不稳定；服务器标签裸用 `text-signal` 与活动态进度条撞色
2. 操作区硬编码 `w-[200px]`——已完成任务只剩「删除」时右侧留 140px 虚空，多操作时又拥挤；工具栏批量按钮无选中预反馈
3. 双层通栏横带感——`toolbar`（bg-surface）与 `overview`（bg-surface-alt）紧贴形成"夹板式"割裂；概览条不可点击、不支持状态过滤（对比 history 页）
4. 活动任务缺视觉锚点、终态任务噪点多——进行中仅靠静态 Badge；拖拽把手对已完成/错误/取消任务无差别渲染，整列灰点无意义
5. 首屏白屏跳闪 + 轮询全量重排——每 tick 对全部已有卡片执行 `appendChild` 挪动，触发不必要 Reflow

## 方向清单（4 条）

1. **重塑卡片信息架构与弹性操作区**（最高性价比）：废弃 `w-[200px]` 改自适应；文件名行 + 次级参数行两行解耦（`·` 分隔）；`errorMsg` 独立成带图标的轻量告警条（`bg-danger-soft/40`）；批量操作按 `selected.size` 联动 disabled
2. **冷灰基调下的状态沉浸**：进行中卡左侧 3px 信号色指示线 + 可选的 2s 微呼吸（`animate-pulse-soft` 走 opacity 合成层）；终态任务弱化拖拽把手噪点
3. **双栏整合与互动式 Filter Chips**（中高性价比）：toolbar 与 overview 合并为一体化 Header；概览指标文本转为带语义色点的可点击 Chip 按钮，点击即筛（前端内存过滤 <0.2ms）
4. **骨架屏 + 轮询管线性能精细化**（保障型）：首屏挂 3~4 张骨架卡；斩断全量 `appendChild`（仅任务增减/拖拽排序才重挂 DOM）；`updateCardDynamic` 只改 `style.width` 不重赋 className

## 不推荐清单（5 项，NAS 陷阱）

大面积毛玻璃（低功耗 NAS 长列表滚动掉帧至 15-20fps）、进度条无限斜纹动画（5~10 任务并发时 CPU/GPU 循环动画）、卡片内 Canvas/SVG 动态小波形（破坏 CardEntry 缓存机制、易内存泄漏）、大面积弥散阴影（破坏 v1.6.0 明度分层约定）、外部图标库/组件库（破坏零依赖构建链）。

## 批次建议（2 个小版本）

- 第一批（v1.6.1 视觉减负与层级速赢，约 60 行零回归风险）：解绑 `w-[200px]`、两行排版 + 独立错误告警条、活动任务左侧边框与微妙呼吸、终态手柄降噪
- 第二批（v1.6.2 交互聚合与性能固化）：Header 一体化、堆叠条升级为 Filter Chips、首屏骨架屏、斩断轮询全量 append

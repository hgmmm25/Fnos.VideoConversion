#### 4.1.1 `src/lib/crudActions.ts` —— CRUD 四件套

```ts
// P2-2：CRUD 四件套统一封装（confirmDialog → api 调用 → toast → reload）
// 只依赖新契约 ApiError（api.ts 已兜底转换旧格式），禁止在公共层出现 body.error 判断
import { confirmDialog, toast } from '../ui'
import { ApiError } from '../api'

export interface CrudActionsOptions<T> {
  /** 删除确认弹窗文案；返回 false 则不弹窗直接取消 */
  confirmTitle: (item: T) => string
  /** 危险操作（删除/不可逆）为 true 时弹窗走 danger 样式 */
  danger?: boolean
  /** 实际 API 调用：action 为 'create'|'update'|'delete' */
  apiCall: (action: 'create' | 'update' | 'delete', item: T) => Promise<unknown>
  /** 成功后的数据刷新（一般传 store.loadXxx） */
  reload: () => void | Promise<void>
  /** 成功文案模板，默认 `${action === 'delete' ? '删除' : action === 'create' ? '创建' : '更新'}成功` */
  successMsg?: (action: 'create' | 'update' | 'delete', item: T) => string
}

export function crudActions<T>(opts: CrudActionsOptions<T>) {
  const run = async (action: 'create' | 'update' | 'delete', item: T) => {
    if (action === 'delete') {
      const ok = await confirmDialog(opts.confirmTitle(item), '确认操作', opts.danger ?? true)
      if (!ok) return
    }
    try {
      await opts.apiCall(action, item)
      toast(opts.successMsg ? opts.successMsg(action, item) : defaultMsg(action), 'success')
      await opts.reload()
    } catch (e) {
      const msg = e instanceof ApiError ? e.message : String(e)
      toast(msg, 'error')
    }
  }
  return {
    create: (item: T) => run('create', item),
    update: (item: T) => run('update', item),
    remove: (item: T) => run('delete', item),
  }
}
```

- **接入文件**：`profiles.ts`（3 处 confirmDialog→api→toast→reload 替换）、`servers.ts`、`tasks.ts`、`history.ts`。
- **验收点**：6 页无手写 `confirmDialog(...).then(...)` + `api.*` + `toast` + `store.load*` 四连样板；删除确认仍保留弹窗。

const positions = new Map<string, number>()

export function saveScrollPos(el: HTMLElement | null, key: string) {
  if (el) positions.set(key, el.scrollTop)
}
export function restoreScrollPos(el: HTMLElement | null, key: string) {
  if (el) {
    const v = positions.get(key)
    if (v !== undefined) el.scrollTop = v
  }
}

#### 4.1.3 `src/lib/useListPage.ts` —— 列表页组合器

```ts
// P2-2：列表页公共流程（订阅 store → 拉数据 → 渲染 → 错误处理 → refresh）
import { toast } from '../ui'
import { ApiError } from '../api'

export interface UseListPageOptions<T> {
  load: () => Promise<T[]>
  render: (data: T[]) => void
  /** 数据变更订阅（store.subscribe），返回取消函数 */
  subscribe?: (cb: () => void) => () => void
  /** 首次加载错误提示文案 */
  errorLabel?: string
}

export function useListPage<T>(opts: UseListPageOptions<T>) {
  let unsub: (() => void) | null = null
  let disposed = false

  async function refresh() {
    try {
      const data = await opts.load()
      if (!disposed) opts.render(data)
    } catch (e) {
      const msg = e instanceof ApiError ? e.message : String(e)
      toast(`${opts.errorLabel ?? '加载'}失败：${msg}`, 'error')
    }
  }

  function mount() {
    if (opts.subscribe) unsub = opts.subscribe(() => void refresh())
    void refresh()
  }
  function dispose() {
    disposed = true
    unsub?.()
    unsub = null
  }
  return { mount, dispose, refresh }
}
```

- **接入文件**：`tasks.ts` / `servers.ts` / `history.ts`（标准"subscribe + 拉数据 + 渲染"三页），再逐步覆盖 `profiles.ts` / `scanner.ts`。
- **验收点**：页面卸载（路由切换）时 `dispose()` 被调用，无订阅泄漏（可借助 main.ts 的 `editorCleanup` 模式对照）。

### 5.2 Svelte 5 试点细则（若触发）

- **试点页**：`history.ts`（189 行，业务最轻）或 `servers.ts`（255 行）——二选一，建议 history.ts。
- **集成方式**：Svelte 5 组件以 custom element（自定义元素）嵌入现有 `el()` 渲染树，**禁止全量重写**；状态共享通过 `store.ts`（保持框架无关的纯 TS + 订阅）跨框架读写。
- **试点步骤**：
  1. 安装：`npm i -D svelte @sveltejs/vite-plugin-svelte`（ui-src 下）；
  2. vite.config.ts 注册 svelte 插件与 custom element 编译配置（`customElement: true`）；
  3. 将 history 页渲染函数替换为 `<fvcc-history>` 自定义元素挂载；
  4. 评估指标（与组合器方案对照）：
     - 打包体积增量：runtime 增量 **< 15KB gzip**，否则回退组合器方案；
     - 首屏耗时、交互一致性、store 读写可行性、构建集成稳定性；
  5. 输出结论文档 `docs/DESIGN.md` 增补"P2-2 框架决策记录"。
- **禁止项**：❌ 试点未通过不得推广；❌ 不得同时引入多个框架；❌ 编辑器区不参与试点。

| 组合器 API 设计不良，演变成"自研框架前身" | 中 | API 保持小而稳定：只封装"流程"，不封装"样式/布局"；严禁把业务判断塞进公共层（Code Review 卡点） |
| 抽取引入行为回归（scrollPos 丢失、订阅泄漏） | 中 | 每页接入后单独走查；dispose 与 mount 对称；对照 main.ts editorCleanup 模式 |
| 错误契约旧格式扩散到公共层 | 高 | grep 卡点：公共层 `body.error` = 0；ApiError 是唯一错误类型 |
| 渐进引入框架后打包体积劣化 | 中 | 试点页独立对比；runtime 增量 >15KB gzip 即回退 |
| 行数指标被"压缩代码"作弊达成 | 低 | 验收同时走查 A3/A4/A9，防止为降行数删功能 |

## 1. 项目定位

Fnos.VideoConversion 是一套**双端远程视频转码与剪辑系统**：

- **FVCC（调度端）**：部署于 NAS，以 Web UI 形式提供转码任务调度、素材管理与后续 Web 剪辑入口；
- **FVCS（渲染端）**：部署于局域网内的高算力 Windows 主机，负责接收任务并调用 FFmpeg 完成转码/渲染，成品回写 NAS 共享目录；
- **freecut**：仓库内含的独立浏览器剪辑编辑器（上游参考项目），提供完整的 Web 端视频编辑能力。

架构要点：素材不离开 NAS，渲染节点通过 SMB 直挂共享目录读写素材与成品，免分片上传/下载链路。

## 4. 现状分析

### 4.1 优点

- 双端架构清晰，调度端（NAS）与渲染端（Windows）职责分离，素材免迁移；
- FVCC 前端零框架、轻量，构建产物小（主 chunk 192.6 KB，图表库异步加载）；
- FVCS 凭据使用 DPAPI 本地加密，渲染端作为挂载方持有凭据，NAS 侧不落明文；
- freecut 提供完整 WebGPU 剪辑能力，可作为 FVCC 编辑器功能的参照与演进方向；
- 工程治理闭环已建立（凭据 AES-GCM 加密 / 删除回收站化 / 后端分层 internal / P0-2 SQLite 迁移 / P1-1 事件驱动调度 / P3-5 store 备份回滚 / 前端组件化 4 件套 / CI + 覆盖率门禁 / 破坏性操作审计闭环），P0/P1/P2 治理项全部落地；
- **1.6.x 两项质量收益**：① v1.6.4 任务页理顺信息层级/错误呈现/加载与选中反馈，立住"视觉改进不得增加 WS tick 重绘"硬约束（进度条 `transform: scaleX(--p)` 合成层 + render/updateOverview 签名守卫）；② v1.6.5 把版本一致性校验从"Windows 静默 SKIP（全绿但零校验）"改为"漂移即红"，根治"发布包元数据与真源长期不一致却无人发现"这类潜伏缺陷（1.6.4 实际发生一次：VERSION 仍 1.6.0，`/api/info` 与「设置」页显示错版本）。
